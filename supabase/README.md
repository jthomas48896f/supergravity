# Atlas backend (Supabase)

The foundation that turns the static atlas into a people-powered commons.

## What's here

```
supabase/
  migrations/0001_foundation.sql   The schema: identity + trust tiers, knowledge
                                   graph, per-claim provenance, contribution/review
                                   ledger, reputation, moderation, personal layer,
                                   AI usage. Apply ONCE to a fresh project.
  seed/apply.cjs                   Loads generated seed JSON into the DB (REST).
  seed/*.json                      Generated by tools/extract-content.cjs (gitignored).
```

## Go-live steps (needs the owner's go-ahead — provisioning may cost money)

1. **Provision a project** in the `supergravity` org. Either restore an existing
   INACTIVE project (likely free within the 2-project free tier) or create a new
   one (**$10/month**). Do NOT use `Lantern` — that's a separate dating app.
2. **Apply the migration** — run `migrations/0001_foundation.sql` against the
   project (Supabase SQL editor, the MCP `apply_migration`, or the CLI).
3. **Extract content** — `node tools/extract-content.cjs` (writes `seed/*.json`).
4. **Seed** — set `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`, then
   `node supabase/seed/apply.cjs`.
5. **Wire the client** — add `SUPABASE_URL` + `SUPABASE_ANON_KEY` to the app and
   replace the fake `auth.jsx` sign-in with real Supabase Auth.

## Trust model (the "human, not bots" backbone)

`profiles.trust_tier` is an ordered enum: `unverified < verified < academic < expert`.

| Tier | How it's earned | Powers |
|------|-----------------|--------|
| unverified | no profile / anon | read, suggest (queued) |
| verified | signed in (email/OAuth) | comment, propose edits, add resources |
| academic | **ORCID / `.edu` SSO / educator check** | author, review, vote |
| expert | tier 3 + peer endorsement + track record | adjudicate, manage subjects |

Tier/reputation/orcid are system-managed (a DB trigger blocks self-promotion);
they're granted by the verification + reputation pipelines running as service_role.
Every contribution records `ai_assisted` + `ai_model` + the accountable `user_id`:
AI may co-author, but a named human always signs for it.
